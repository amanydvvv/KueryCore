## 3. How the Pipeline Works

### 3a. Document Ingestion

**Endpoint:** `POST /api/documents/upload`  
**Auth:** Bearer JWT required  
**Flow:**

```
Client ΓöÇΓöÇmultipart/form-dataΓöÇΓöÇΓû║ POST /api/documents/upload
                                  Γöé
                              documents.py::upload_document()
                                  Γöé 1. Validate extension (pdf/md/txt)
                                  Γöé 2. SHA-256 dedup check
                                  Γöé 3. Write raw_bytes to Document row (status=pending)
                                  Γöé 4. Dispatch background task:
                                  Γöé       ingestion.py::ingest_document()
                                  Γöé           Γö£ΓöÇΓöÇ pymupdf text extraction
                                  Γöé           Γö£ΓöÇΓöÇ OCR fallback (Groq vision) for blank pages
                                  Γöé           Γö£ΓöÇΓöÇ LangChain RecursiveCharacterTextSplitter
                                  Γöé           Γöé   (chunk_size=800, overlap=200)
                                  Γöé           Γö£ΓöÇΓöÇ Gemini embed_documents() ΓåÆ 768-dim vectors
                                  Γöé           ΓööΓöÇΓöÇ INSERT chunks + embeddings ΓåÆ pgvector HNSW
                                  ΓööΓöÇΓöÇ Returns DocumentResponse (status=pending)
```

**Sample request:**
```bash
curl -X POST http://localhost:8000/api/documents/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@my_doc.pdf"
```

**Sample response:**
```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "filename": "my_doc.pdf",
  "display_title": "My Document",
  "file_type": "pdf",
  "file_size": 204800,
  "status": "pending",
  "chunk_count": 0,
  "created_at": "2026-11-03T10:00:00Z",
  "updated_at": "2026-11-03T10:00:00Z"
}
```

### 3b. Question Answering (RAG Pipeline)

**Endpoint:** `POST /api/chat` (blocking) or `POST /api/chat/stream` (SSE)  
**Auth:** Bearer JWT required  
**Flow:**

```
Client ΓöÇΓöÇJSONΓöÇΓöÇΓû║ POST /api/chat
                    Γöé
                chat.py::chat()
                    Γöé 1. Guardrails: is_injection() check on question
                    Γöé 2. PII sanitization: sanitize_pii()
                    Γöé 3. Intent routing: classify_intent() ΓåÆ GENERAL / TECHNICAL / CONCEPTUAL
                    Γöé    ΓööΓöÇΓöÇ adjusts top_k dynamically
                    Γöé 4. Follow-up rewrite: rewrite_followup() if prior turns exist
                    Γöé    ΓööΓöÇΓöÇ standalone retrieval query via Groq (deictic resolution)
                    Γöé 5. Retrieval: retrieve_context()
                    Γöé    Γö£ΓöÇΓöÇ Stage 1A: pgvector HNSW cosine similarity (top 20)
                    Γöé    Γö£ΓöÇΓöÇ Stage 1B: PostgreSQL FTS GIN (BM25 lexical, top 20)
                    Γöé    Γö£ΓöÇΓöÇ Fusion: Reciprocal Rank Fusion (k=60) ΓåÆ top 10
                    Γöé    ΓööΓöÇΓöÇ Stage 2: phrase-coverage re-ranker ΓåÆ top 5
                    Γöé 6. Generation: get_llm() cascade (Groq primary ΓåÆ fallbacks ΓåÆ Gemini)
                    Γöé    ΓööΓöÇΓöÇ RAG_PROMPT_TEMPLATE with CoT tags (<thought_process>/<answer>)
                    Γöé 7. Output guardrails: validate_output() (PII leak / prompt injection)
                    Γöé 8. Persist: Conversation + Message rows, QueryLog
                    ΓööΓöÇΓöÇ Returns ChatResponse {answer, citations, latency_ms, avg_similarity}
```

**How to get answer AND retrieved contexts programmatically:**

The non-streaming endpoint returns `citations` which are the retrieved chunks:

```bash
curl -X POST http://localhost:8000/api/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "What is the HNSW index used for?",
    "document_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "conversation_id": null,
    "top_k": 5
  }'
```

**Sample response:**
```json
{
  "answer": "The HNSW index is used for approximate nearest-neighbor vector search...",
  "citations": [
    {
      "chunk_id": "abc123...",
      "document_id": "3fa85f64...",
      "filename": "my_doc.pdf",
      "page_number": 3,
      "score": 0.872,
      "content_preview": "HNSW (Hierarchical Navigable Small World) index provides..."
    }
  ],
  "conversation_id": "def456...",
  "latency_ms": 1240,
  "avg_similarity": 0.847,
  "intent": "TECHNICAL"
}
```

For **eval purposes**, `citations[].content_preview` gives the retrieved chunk text (up to 300 chars). For full chunk content, query the DB directly via `GET /api/documents/{id}` or the internal `retrieve_context()` service.

## 6. Existing Eval Infrastructure

An internal eval harness already exists at `backend/scripts/run_eval.py` with:
- 37-entry golden dataset (`backend/results/baseline.json`)
- Judge model: `openai/gpt-oss-20b` via Groq, temperature 0
- Metrics: marker_recall, retrieval_quality, groundedness, completeness
- Baseline (Aug 2026): 100% marker recall / 93.9% retrieval / 100% groundedness / 93.9% completeness

**Phase 2 will extend this** with a DeepEval-based external evaluation suite using standard LLM-eval metrics (Faithfulness, Answer Relevancy, Contextual Precision, Contextual Recall).
